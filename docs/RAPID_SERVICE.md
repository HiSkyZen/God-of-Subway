# 급행 운행 로직

## 지원 노선

현재 엔진에서 급행↔완행 서비스 전환 후보를 평가하는 노선은 다음 6개입니다.

- 1호선
- 4호선
- 9호선
- 경의중앙선
- 수인분당선
- 경춘선

공항철도 직통열차는 이 후보군에 포함하지 않습니다. 빌드 단계에서도 공항철도 직통열차를 생성 시간표에서 제외하므로 일반 공항철도 열차와 직통열차를 급행↔완행 관계로 오인하지 않습니다.

## 서비스 판별

`src/engine/rapid-service.ts`는 급행 대상 노선에서 열차 `service` 문자열의 `급행/특급/express/rapid` 표기와 정차 패턴(`stop.call === false`)을 함께 사용합니다. `직통/direct` 문자열 자체는 급행 판별 기준이 아닙니다.

KRIC 빌드에서는 `exptCd`를 `local/express/direct`로 정규화하지만, 공항철도 `direct`는 `trip` 적재 전에 제거합니다. 기타 노선의 `direct` 표기는 일반 열차로 낮춰 저장하여 런타임의 급행 후보가 문자열 오분류에 의존하지 않도록 합니다.

## 급행↔완행 환승 후보

기본 그래프 후보를 만든 뒤 급행 운영 노선의 각 구간에서 실제 SQLite 시간표를 조회합니다. 중간역 전후에 `rapid`와 `local` 서비스 조합이 존재하면 동일 노선 2개 세그먼트로 분할한 0초 제자리 환승 후보를 추가합니다.

후보 생성 자체가 추천을 확정하지 않습니다. 최종 ETA 계산이 전체 여정 도착시각을 비교하여 실제로 이득이 있는 후보만 선택합니다. 같은 시각 조건에서는 service priority가 안정적인 tie-break에만 관여하며 실제 예상 도착시각보다 우선하지 않습니다.

## 불변조건

- 급행 노선명만으로 열차를 급행으로 가정하지 않습니다.
- 급행 미정차역에서는 급행↔완행 전환 후보를 만들지 않습니다.
- 공항철도 직통은 급행 후보가 아닙니다.
- 실제 시간표가 없는 synthetic 서비스 분류로 ETA를 앞당기지 않습니다.
